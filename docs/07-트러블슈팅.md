## 2. 자유 질문이 거의 동작하지 않음

### 문제

초기 Copilot은 추천 버튼이나 특정 키워드에서는 동작했지만 사용자가 자연스럽게 질문하면 의도를 제대로 찾지 못했습니다.

E0:

```text
Intent exact match
1 / 100
```

### 원인

deterministic keyword router가:

- `확인`
- `적용`
- `왜`
- `변경`

같은 substring에 과도하게 반응했습니다.

예:

```text
“중소기업 확인서가 적용되는지 설명해줘”
```

에서 실제 의미보다 `확인`, `적용` 같은 단어가 먼저 잡혔습니다.

### 개선

```text
명확한 UI intent / write
→ deterministic 유지

UNKNOWN / weak read
→ Semantic Router

Semantic 실패
→ deterministic fallback
```

### 결과

```text
E0   1 / 100
E1  41 / 100
E2 100 / 100
```

### 배운 점

> 키워드를 계속 추가하는 것보다 **어떤 요청만 의미 분류로 넘길지 경계를 설계하는 것**이 중요했습니다.

## 3. Dense Retrieval만으로 필요한 근거를 잘 찾지 못함

### 문제

공공입찰 문서에는 자연어뿐 아니라:

- 업종코드
- 금액
- 기관명
- 확인서 명칭
- 법령 표현

처럼 lexical matching이 중요한 값이 많습니다.

Dense:

```text
Recall@4 29.17%
```

### 개선

동일 fixture에서:

```text
Dense             29.17%
Hybrid            50.00%
Hybrid + Rerank   55.56%
```

### 기술 선택

Rerank가 가장 높은 Recall을 보였지만 p50 latency가 약 2.85초로 증가했습니다.

따라서 기본 검색 전략은 Hybrid로 선택하고 Rerank는 기본 적용하지 않았습니다.

### 배운 점

> 가장 높은 offline metric이 항상 가장 좋은 Product 선택은 아닙니다.

## 4. Citation이 있어도 답변이 틀릴 수 있음

### 문제

Citation 존재 자체가 Grounding 품질을 보장하지 못했습니다.

- 질문과 관계없는 Source를 Citation
- 일부 조건만 근거가 있는데 전체 조건 확정
- 불완전한 원문 값을 모델이 “정상적인 값”으로 복원

### 개선

```text
v1 Citation 존재
↓
v2 직접 근거 없으면 abstain
↓
v3 partial evidence를 전체 결론으로 확대 금지
↓
v4 원문 오류 임의 복구 금지
```

### 이후

v3.1에서 Prompt만이 아니라 구조 자체를:

```text
Fact
Source
Claim
Validation
```

으로 분리했습니다.

### 배운 점

> “근거를 붙여라”보다 **그 문장이 그 근거로 실제 뒷받침되는지 검증하는 구조**가 필요했습니다.

## 5. 자동테스트가 통과해도 생성문이 서버 상태와 반대일 수 있음

### 문제

v3.1 감사 과정에서 확인한 위험:

- 저장 판정과 반대되는 생성 산문
- 수동 확인 항목의 Source 연결 누락
- 오래된 index/source의 재사용
- 복합 답변 중 일부 Unsupported Claim

### 개선

```text
Server Fact
→ Source
→ Model Draft
→ Mechanical Validation
→ Semantic Validation
→ 필요 시 Repair 1회
→ Supported Claim만 게시
```

응답 직전 현재 Scope와 fingerprint도 다시 확인합니다.

### 결과

지원되지 않는 Claim을 삭제하거나 PARTIAL로 반환합니다.

남원 Guided Job 24턴 중 1건도 잘못된 Fact 참조 Claim이 제거되어 COMPLETE가 아니라 PARTIAL로 남았습니다.

### 배운 점

> 실패를 숨겨 완전한 답처럼 보이게 하는 것보다 **안전한 부분 성공을 반환하는 것이 중요**했습니다.

## 6. 높은 안전성을 얻었지만 응답이 느려짐

### 문제

v3.1은:

- Planning
- Product Read
- Generation
- Claim Validation
- 필요 시 Repair / Revalidation

을 수행합니다.

Guided Job 실제 모델 평가:

```text
평균 약 26.92초
최대 약 54.13초
```

### 현재 판단

안전 검증을 제거해 속도를 얻기보다:

- Guided Job 고정 TaskPlan
- 불필요한 모델 호출 축소
- selective validation / retrieval
- hard query에서만 추가 처리

방향이 적합하다고 판단했습니다.

### 배운 점

> AI 제품 품질은 정확도 하나가 아니라 **정확성 × 안전성 × latency × 비용**의 균형입니다.

## 7. 변경공고 후속 차수 누락

### 문제

Golden 공고의 나라장터 원문을 직접 대조하면서:

```text
팀 DB Current Version
≠ 나라장터 실제 최종 차수
```

인 사례를 발견했습니다.

우치공원 `R26BK01634263`은 DB에 003까지만 존재했지만 실제로는 004·005가 있었습니다.

### 개선

- 신규 공고 전체 이력 Backfill Queue
- 기존 공고 점진적 Backfill
- 차수 순 정렬
- 최신 차수 Current 지정
- 중복 방지
- 항목별 수집 오류 격리

### 결과

```text
R26BK01634263
000 ~ 005
```

전체 6개 차수를 저장했고 `005` 취소공고까지 현재 Version으로 확인했습니다.

### 배운 점

> 수집 파이프라인의 “성공”과 **업무적으로 최신 공고를 확보했다는 것**은 별도 검증이 필요합니다.

## 8. 지역 정보가 부족한데 미달로 확정

### 문제

변경공고에서 지역 요건이:

```text
전남광주통합특별시
→ 종전 광주광역시
```

처럼 좁아졌을 때, 회사 Profile에 상위 지역만 존재하면 실제 세부 지역을 알 수 없습니다.

기존 문자열 비교는 이를 `UNSATISFIED`로 확정할 수 있었습니다.

### 개선

```text
하위 지역 Profile × 상위 지역 Requirement
→ SATISFIED

상위 지역 Profile × 하위 지역 Requirement
→ UNKNOWN

서로 다른 형제 지역
→ UNSATISFIED
```

### 결과

정보 부족을 미달로 확정하는 경로를 차단했고 이 동작을 Golden Regression으로 고정했습니다.

### 배운 점

> B2B 자격판정에서는 “모른다”를 정확하게 표현하는 것이 잘못된 불가 판정보다 중요합니다.

---

## 9. Rule Version이 바뀌었는데 과거 판정을 재사용

### 문제

지역 판정 의미가 달라졌는데 과거 `qualification-rules-v0.2` 결과를:

- 변경 재검증
- Frontend
- Copilot

에서 현재 결과처럼 읽을 수 있는 stale path가 있었습니다.

### 개선

- Rule Version → `qualification-rules-v0.3`
- 현재 Rule과 다른 과거 Judgment 재사용 차단
- Frontend도 v0.3 기준으로 정렬
- Copilot Product Read도 current rule만 사용
- stale source면 fail-closed

### 배운 점

> Rule이 바뀌면 코드만 바꾸는 것이 아니라 **저장된 과거 판정의 의미도 함께 Versioning**해야 합니다.

## 10. 문서가 코드보다 오래됨

### 문제

빠른 개발 중 상위 docs에:

- Copilot Proposed
- Copilot API 미구현
- 과거 Rule Version
- 이전 Product Baseline

이 Current처럼 남았습니다.

### 개선

문서 상태:

```text
Current
Proposed
Baseline Snapshot
Historical
Superseded
```

최종 문서 정리 순서:

```text
Code / Test
→ 구현 저장소 Current docs
→ 제출용 docs
→ README
```

### 배운 점

> AI로 개발 속도가 빨라질수록 **설명 가능한 현재 상태를 유지하는 문서 관리**가 더 중요합니다.
